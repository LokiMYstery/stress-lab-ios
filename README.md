# Stress Lab

独立 iPhone HealthKit 验证工具：RMSSD 离散测量 + 实验实时压力柱状图。仅供产品/算法调试，不用于医疗判断，也不代表 StressWatch 的实现。

## 打开与安装

1. 用 Xcode 打开 `StressLab.xcodeproj`，选择 `StressLab` scheme。
2. 选择 iPhone 模拟器即可编译查看空态。UI 测试自动通过 `--demo` 加载明确标识的模拟数据；模拟数据分支只编译到模拟器。
3. 真机请选择自己的连接设备，并在 Signing & Capabilities 中选择有 HealthKit 权限的开发团队。工程使用独立 bundle ID `art.qiyin.stresslab`，不会替换别急。
4. 点击 Run 安装，打开 App，点击授权读取。授权仅为 read，不会写入或删除 Apple 健康记录。
5. 如无数据，在系统健康权限里检查本 App 的读取项，并等待 Apple Watch 向手机同步。空查询无法区分未授权、没有记录或尚未同步。

最低 iOS 17；开发环境 Xcode 26.3。工程文件已提交，不必安装项目生成工具。若修改 `project.yml`，可用本机已有 `xcodegen generate` 重新生成；无第三方运行时依赖。

## 使用

- 首页两个看板使用同一天与同一时区。向前最多回看六天，加今天共七天。
- 轻点 HRV 图上的圆点，或点图下方的时间按钮，可查看该次 RMSSD 的四档实验状态、参考分和判断依据。记录页可查看无效测量及过滤原因。
- 图下诊断会列出被过滤的逐拍记录、其他手表来源的逐拍记录，以及在当前来源未配对到逐拍记录的 Apple SDNN。可点“其他来源逐拍”切换来源核对；SDNN 只能提示可能缺失的测量，不能直接换算成 RMSSD。
- 实时压力是按六分钟时间格回算的实验估算，绝不是硬件每六分钟重新测量 HRV。未来没有柱子；没有实际 RMSSD 或心率输入的历史时间格不填默认分。
- App 前台每分钟重评数据时效，防止旧测量永远被当成新鲜；这只更新本地计算，不会触发手表采样。
- 后台刷新期间保留已有图表；短时间内连续到达的 HealthKit 通知会合并读取。
- 睡眠阴影来自选定来源的实际睡眠记录；清醒/睡眠独立基线。无睡眠记录并不证明人实际清醒。
- 设置可选择数据来源和参数版本；有稳定设备标识时按设备隔离个人基线。
- 无稳定设备标识的记录归入“身份不明确”组。仍可按该组记录作实验估算，但会标记设备来源不确定；若同时使用多块同型号手表，结果可能混用，不能当作可靠的个人基线。
- 实验参数点“重新计算”才生效；每次保存新版本，可切回 V0/V1/V2 或恢复 V3 默认参数。
- 旧日期第一次完成回算后，把报告按日期、时区、来源和参数版本保存在本机；之后切天立即显示缓存。当天始终重新计算。旧日期按右上的刷新按钮可主动重算，以纳入迟到的 HealthKit 数据。
- 当前 Agent 参考卡仅为输出预览，不发送数据或调用 Agent。无可用判断时给默认 50，并明确标为 default；50 不是医学正常值。

## 数据与隐私

HealthKit 数据只读。本机私有缓存采用文件保护、原子写入且目录不参与备份；没有网络、账号、第三方分析或云同步。

缓存使用首次解锁后的文件保护，允许系统后台唤醒时访问本机计算快照；重启后首次解锁前不可访问。HealthKit 自身的数据保护独立于本 App，锁屏时查询可能失败；失败会保留快照并等待后续更新或回前台重试。

首次读取最多三十七天：七天图表加前置三十天基线。当前进程通过 anchored query 增量读取、处理删除；重新启动做有界全量读取，避免仅存 anchor 导致记录与游标不一致。刷新失败保留上次完整快照。

“清除本地数据”只移除本 App 的缓存和实验版本，不删除 Apple 健康原始数据；再次授权/刷新可以重新读取。模拟数据不保存进真实缓存。

## 健康数据更新通知（真机实验）

设置 → 健康更新通知 → 开启“健康变化通知”，允许系统通知与健康读取。开关默认关闭，开启时以当前已读记录建立基准；首次同步不推历史消息。之后选定来源有新的可计算 RMSSD 时，发送一次本地通知，显示 RMSSD、该 HRV 点参考分、基线状态、采样时间和读取时间。通知点击后跳到该测量日期。补传超过三小时、未来时间、不可计算序列、运动/正念排除、当前移动或运动恢复阻断，以及模拟数据均不触发；同批多个点只提醒最新有效点。UUID 去重在本机持久化，重复回调、调参和切天不会重复提醒。

普通心率更新可唤醒 App 并重新估算压力、刷新看板；从 2026-10-08 起，新增可开关的“心率压力趋势提醒”，默认开启。它比较最近 15 分钟与 60–75 分钟前的数据：每窗至少三个实际五分钟格、采样覆盖至少八分钟、最新有效心率不超过五分钟；只用明确 sedentary、清醒、无运动恢复冲突的样本。整个比较跨度有已知睡眠或运动/恢复时跳过。运动元数据缺失时不发趋势通知，但看板仍按原规则估算。

两窗口使用目标时刻同一份个人心率基线（至少三个此前完整日），按五分钟格等权取中位数，再使用当前模型的普通心率映射；不混入 HRV、静息心率，也不受 HRV 权重过期和看板突变标红规则影响。因此趋势分可能不同于看板综合分。参考分变化至少 15 分、窗口心率中位数变化至少 8 bpm、最近两格持续达到相同方向门槛才通知。趋势通知最短间隔 60 分钟；同方向持续变化不重复提醒，差值回落到门槛一半以下才重新允许同方向提醒，反向变化也受间隔约束。新 HRV 优先，成功提交新 HRV 通知后十五分钟不发趋势通知。

设置支持调整窗口（15–30 分钟）、对比距离（45–120 分钟）、分数门槛（10–30 分）与间隔（30–120 分钟），并显示最近两窗口分数及有效格数量。修改参数、来源或模型版本时先重建趋势游标，避免立即重放历史。旧逐次心率通知设置不再生效。首次同步、重复样本、默认参照基线和不足窗口不触发趋势通知。这些门槛用于产品实验，需真机观察后调整；自动健康通知现按当地时间 23:00–07:00 停发，不补发夜间压力提醒；手动测试按钮不受该时段限制。

真机试法：

1. 先点“发送测试通知（5 秒后）”，验证本地通知展示。它不验证 HealthKit 后台唤醒，也没有健康数值。
2. 开启新 HRV 通知并完成首次读取，返回桌面保留 App 在后台，等待 Watch 的下一份实际数据同步。可通过手表正念呼吸促成采样，但最终是否采样和何时同步由系统决定；若该样本带正念记录，当前模型会排除它，因此未必提醒。
3. 通知中比较“采样/读取”时间；未看到通知时回设置查“后台接收”“最近健康更新回调”和通知提交状态。最后一项是提交给系统，并不证明用户已看到通知。
4. 分别测试锁屏和解锁、跨午夜、同一数据重复刷新、关闭后重开、专注模式/系统通知关闭。关闭通知或清除本地数据会停止后台注册，清除动作也移除本 App 已展示通知。

实现采用 `HKObserverQuery` + `enableBackgroundDelivery(.immediate)` + `UNUserNotificationCenter`。启动时在 App delegate 注册观察者；更新回调等待读取、计算、提交通知后才调用 HealthKit completion。当前对心跳序列、SDNN、心率和睡眠请求后台接收；各类型的注册失败会显示具体错误，SDNN 到达后仍需等待逐拍序列才能产生 RMSSD 通知。iOS 可延后或合并唤醒，不能保证每次采样立即通知；这不是六分钟后台计时器，也没有接入服务器推送。只读查询不启动 Watch 主动采样。没有 Watch App，手表提醒是否镜像由用户的 Watch 通知设置决定。

后台 HealthKit 查询不支持模拟器；模拟器只验证 UI、计算与本地通知。重新签名安装时，配置需包含新增 `com.apple.developer.healthkit.background-delivery` entitlement。[Apple 后台观察说明](https://developer.apple.com/documentation/healthkit/executing-observer-queries)、[后台接收权限](https://developer.apple.com/documentation/xcode/configuring-healthkit-access)。

## 实验模型与校准

逐拍间隔 → 原始/过滤 RMSSD → lnRMSSD 个人基线；非运动时段的近期心率 → 六分钟中位数 → 个人心率基线。明确静止的心率优先；活动标记缺失且无运动冲突时作为低置信度输入。基线只使用目标日期之前的完整日，按日等权；不使用未来健康记录。

V0 保留原先 `round(50 + 20*z)` 的压力映射。V1 根据 2026-09-21 至 23 日成对截图提出较温和的校准候选：心率尺度下限 8 bpm、RMSSD 对数尺度下限 0.25、RMSSD 权重 1.5 小时衰减；压力升高方向斜率 8，恢复方向斜率 15。有选定来源的近期静息心率及历史基线时，它在心率通道的默认权重为 65%；没有可用静息心率则继续用短时心率。例如 `z=+2` 时 V0=90、V1=66，`z=+4` 时 V1=82。

V2 保留 V1 的基础分数，但默认关闭 RMSSD 时长、组数、RR 范围质量门槛，以便查看过去被这些门槛挡掉的点。漏拍、倒序和无效时间仍是计算断点；至少需要两组相邻有效 RR 才能得出 RMSSD。V2 在原始分达到 81–100 后，还要求此前 30 分钟有足够记录、相对其分数中位数上升至少 20 分、相对最近一格上升至少 15 分，并在两次红色之间间隔 45 分钟；否则上限显示为橙色 80 分。

V3 默认延续 V2 的逐拍显示和红色规则，把 HRV 点分数经过单调 S 曲线校准：`4 + 96 / (1 + exp(-0.155 × (V2点分 - 50)))`。刚测得 HRV 后首个六分钟压力格先与该点分数一致；存在心率通道时，之后 1.5 小时内逐渐转向心率分数。新版仅在 Apple Watch 心率样本明确标记 `active` 后的五分钟内，把该时间格判为频繁移动并留空；步数不参与默认判定。明确的运动记录及恢复期仍单独排除。旧参数版本保留先前的步数规则供历史结果复现。未附活动标记的真实移动可能无法识别。V0/V1/V2 仍可选择。V3 对齐的是用户提供的 HRV 点开压力分数，不能保证与 StressWatch 私有模型逐格一致。

历史不足时先用已有个人历史临时比较；没有个人历史时，使用可调产品参照（默认 RMSSD 50 ms、心率 70 bpm，尺度分别为 0.5 和 10 bpm），并标记为默认参照。它们不是医学正常值或 StressWatch 的公开参数。截图不足以证明数值已对齐，详见 [研究说明](docs/RESEARCH.md)。

删除、补传、更新数据或切换参数后历史结果可以改变。当前版本重建“当时采集到的数据”的回算，不重现当时手机尚未同步时的可见状态。

## 真机对照步骤

1. 先核对来源、采样日期、最后同步时间和三十天覆盖。
2. 在两 App 中找同次 HRV 测量，比较 RMSSD；不与 Apple SDNN 直接比较。
3. 检查过滤前后值、缺口和睡眠/正念/运动标记，定位数值差异。
4. 再比较同一时段压力趋势，确认两端数据都已同步；记录所用参数版本。
5. 调参后用不同日期验证，不只调到某一张图看起来相似。

不需要也不建议为了本工具开启房颤历史功能。真机安装/健康读取尚需设备所有者在自己的设备上授权；不得把模拟器截图当成真实健康数据证据。

## 主睡眠结束提醒（2026-10-26 实验）

设置中“健康变化通知”为总开关；“主睡眠结束提醒（实验）”默认随总开关可用，可单独关闭。固定静默时段当地 23:00–07:00，不提交自动通知。

同来源睡眠阶段去重合并（间隔最多 90 分钟），实际睡眠至少 3 小时，覆盖夜间 00:00–06:00 的某部分，总跨度不超过 18 小时，才视为夜间主睡眠候选。多来源分别计算，不叠加，同一夜只通知一次。末段结束 30–120 分钟、没有后续睡眠记录时，在健康更新或前台刷新中检查。首次同步只建基准，不补发历史；失败可重试；后台没有 30 分钟计时器。

标题“一段休息之后，慢慢开始”；正文“本次记录到睡眠 X 小时 Y 分钟。让一段音乐，陪你找到接下来的节奏。”点击定位睡眠结束日期的看板。设置页显示等待、静默、过期或已提交原因。实验不承诺实时醒来检测，不覆盖午休或轮班睡眠；需真机观察同步延迟和短暂醒来误报。
